# Sonic 音频更新节奏

默认 `WasapiLoopbackCapture` 通过 `WasapiCapture` 使用 100 ms 缓冲、半缓冲周期轮询。每次唤醒会连续排空多个音频包，平均 FFT/s 掩盖了发布之间约 60 ms 的空档。Sonic 直接将 `LatestFeatures` 传入高度图，因此中央方块会保持数帧再跳变。

改为继承 `WasapiCapture`，启用设备事件同步、请求 20 ms 缓冲，并保留 Loopback 标志。初始化和设备恢复使用相同类型。FFT 窗口、特征平滑和 shader 不变。

2026-09-27，本机 96 kHz 混音设备，8 秒低音量调幅测试音，实际 SpectrumAnalyzer 回调：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 回调数量 | 759 | 799 |
| 平均间隔 | 10.40 ms | 10.00 ms |
| 最长间隔 | 63.17 ms | 12.16 ms |
| 小于 2 ms 的突发间隔 | 629 | 0 |
| 大于 25 ms 的空档 | 127 | 0 |

在本目录执行 `dotnet run --project AudioProbe.csproj -c Release -- --tone` 可复测；会播放 8 秒低音量测试音。无 `--tone` 则仅观察现有播放。回归断言检查回调数量、空档比例和突发比例：修改前失败，修改后通过。时间阈值允许少量系统调度抖动。

该结果验证了实际采集链路的节奏改善；未对当前运行的旧版程序做替换或视觉验收。对旧进程的 GC EventPipe 采集因诊断管道访问被拒绝而未完成，因此不据此声称排除了所有 GC 停顿。
